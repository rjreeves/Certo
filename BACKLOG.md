| 122 | `withTimeout(Duration) { ... }`, supervised `spawn`/`every()` (periodic background jobs) | Split out of item 80 after actually implementing and shipping the other third of it (`Channel<T>` — see item 80 in the Completed table above). `spawn`/`await`/`parallel {}`/`Channel<T>` are all real today, but the runtime has **no task-cancellation mechanism at all** — once `spawn` starts an OS thread, it always runs to completion; there is no cancel-flag, no cooperative check-point, no OS-level thread termination anywhere in the codegen or C runtime. `parallel(timeout:)` (item 81) deliberately sidesteps this rather than solving it: on timeout it panics and *leaks* the thread/handle rather than stopping it, which only works because the process is about to exit anyway. `withTimeout(d) { body }` needs the opposite — the scope's task(s) must actually stop (or at least be abandoned in a way the rest of the program can safely ignore) so execution can *continue* past the timeout, not panic.
