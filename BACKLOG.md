A real implementation needs, at minimum: (1) a cancellation token/flag threaded through every spawned task's context struct, checked at defined points (loop back-edges? every `await`? — the spec doesn't say); (2) codegen support for inserting those check-points into generated worker functions; (3) `every(Duration) { body }`'s own scheduling loop (a timer thread that re-spawns `body` on each tick) plus "supervision" semantics for `spawn` that spec section 7.3 alludes to (`startBackgroundJobs()`'s example) but never defines precisely (restart on panic? how many times? backoff?). None of this can be bolted onto `Channel<T>`'s mutex/condvar pattern or `parallel(timeout:)`'s leak-and-panic pattern — it needs its own cancellation primitive in `crates/codegen/src/emit_module.rs`'s runtime prelude first, which is why it's scoped out here rather than attempted as a partial slice (a `withTimeout` that doesn't actually stop anything, or an `every()` with unspecified restart behavior, would be worse than not having them, per this project's own standard for items 76/117/118). |
